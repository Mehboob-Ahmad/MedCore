# 🗄️ Database

This directory contains all database-related assets for the MedCore platform.

## Architecture Rationale

Centralizing database assets outside the backend ensures:

- **Visibility** — Schema changes are easily auditable in code review
- **Reproducibility** — Any environment can be bootstrapped from scratch
- **Safety** — Migrations are versioned and reversible
- **Collaboration** — Database changes follow the same PR workflow as application code

## Structure

```
database/
├── migrations/   → Versioned database migration scripts
├── seeds/        → Initial and test data seeding scripts
├── schema/       → ERD definitions, raw SQL schema exports
└── backups/      → Backup scripts and restoration procedures
```

## Directory Details

### `migrations/`
Ordered, versioned migration scripts generated by Entity Framework Core or written manually. Each migration represents an atomic, reversible schema change.

### `seeds/`
Data seeding scripts for:
- **Development** — Realistic test data for local development
- **Staging** — Sanitized production-like data
- **Production** — Essential reference data (roles, permissions, specialties)

### `schema/`
Visual and textual representations of the database schema:
- Entity Relationship Diagrams (ERDs)
- Raw SQL `CREATE TABLE` exports
- Schema documentation

### `backups/`
Scripts and procedures for:
- Automated backup scheduling
- Point-in-time recovery
- Cross-environment restoration
